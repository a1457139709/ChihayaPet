# Domain Docs

Use a single-context layout: `CONTEXT.md` at the repository root and decisions under `docs/adr/`.

## Before exploring

Read root `CONTEXT.md` for domain vocabulary and any ADRs in `docs/adr/` relevant to the work. If a root `CONTEXT-MAP.md` is introduced later, follow its pointers to the relevant contexts.

When these files do not exist, proceed silently. The domain-modeling skill creates them when terminology or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in issue titles, proposals, hypotheses and tests. If a needed term is absent, check existing project language and record a real gap for domain-modeling.

If a proposal contradicts an ADR, cite the ADR and explain why the decision should be reopened.
