# 妃宫千早 macOS 桌宠设计方案

设计日期：2026-09-05；修订日期：2026-09-07。状态：静态首版已实施；2026-09-08 实际验证结果见 [VALIDATION.md](VALIDATION.md)。本文保留原始设计与验收要求。

## 1. 目标与边界

为用户自己的 M 系列 Mac（macOS 26、48GB 内存）制作可长期放在桌面的千早立绘伙伴，具备换装、鼠标交互和云端 AI 文字聊天能力。

首版必须能在不运行原游戏的情况下独立工作。素材仅使用本资料包中的夏服、冬服 PNG；不需要游戏程序、数据封包、存档或外部图片目录。

第一版采用原作立绘互动，不制作 Live2D、Q 版行走、闭眼或嘴型动画，也不实现语音、本地模型、长期记忆、游戏资源解包、开机自启动或公开发布流程。云端模型不调用工具，不读取屏幕或用户其他文件。

静态首版是可独立交付的阶段性原型，Live2D 仍为后续目标，素材准备和模型制作单独推进。未来 App Store 发布另立阶段，包含素材替换或授权及发布适配，不属于首版验收。

交付环境为 macOS 26.0 及以上，目标架构 arm64。Windows 可以编辑资料和源码，但不能替代 Mac 上的原生构建、本地文件权限和窗口行为验收。

## 2. 技术结构与模块职责

使用 Swift、AppKit、SwiftUI、Foundation 的 URLSession 与本地 JSON 配置。创建原生 Xcode macOS App 工程；静态首版无需第三方运行时、数据库或模型 SDK，后续 Live2D 运行时在模型验证阶段另行确定。

| 模块 | 职责与边界 |
| --- | --- |
| 应用入口与菜单栏 | 管理应用生命周期、显示隐藏、设置和退出；使用菜单栏应用模式，不常驻 Dock 图标 |
| 桌宠窗口控制 | 管理 AppKit 透明窗口、位置、显示器、层级、拖动和穿透；不处理网络 |
| 角色展示 | 独立处理资源加载、图片显示尺寸更新、动效暂停／恢复及释放；首版实现 PNG 展示，保持比例和 alpha，不持有窗口或聊天状态 |
| 聊天界面与会话 | 管理 SwiftUI 面板、气泡、内存消息、上下文裁剪和请求状态 |
| 模型客户端 | 接收连接配置及文本消息，异步返回回复或分类错误，支持取消；允许注入模拟实现 |
| 请求协调 | 为聊天和测试连接共享单请求名额；记录请求标识、配置快照及代次，隔离取消和失效结果 |
| 偏好与凭据 | 使用本地偏好保存非敏感设置，按用户选择使用本机文件保存明文密钥；不持久化聊天 |

数据流：用户输入 → 会话组装角色提示词和近期上下文 → 请求协调捕获配置快照、从凭据存储读取密钥并取得请求名额 → 模型客户端使用该快照请求云端 → 协调层核对请求标识和代次 → 会话接收有效回复 → 面板和气泡更新。所有 UI 更新回到主线程；窗口拖动和换装不依赖网络请求完成。

内部接口至少表达连接配置（基础地址、模型）、带角色的文本消息（system/user/assistant）和可取消的异步回复操作。凭据通过专用存储读取，不混入消息模型或普通设置序列化。应用不提供对外服务端 API。

角色展示接口接收角色资源标识、图片显示高度和动效开关，提供加载／换装、尺寸更新、暂停／恢复及释放操作；点击作为事件交给外层交互控制。窗口位置、焦点与会话生命周期由各自模块持有。首版只实现 PNG 展示器，不引入未使用的 Live2D SDK；后续渲染替换沿用上述职责边界。

## 3. 角色素材与桌面行为

### 素材

- [夏服](../assets/chihaya-summer.png)和[冬服](../assets/chihaya-winter.png)均为 441×516 PNG，支持透明及半透明像素。
- 洋红色背景像素的 alpha 为 0，不需要抠图；保留头发边缘的半透明像素，不进行二值化。
- 两张是下半身被裁切的立绘，不视为全身动作帧。保留版权文字，不重新绘制、裁去版权或改变原图。
- 资源名使用 `chihaya-summer`、`chihaya-winter`，从应用 Bundle 加载，不访问资料包外的原始路径。
- `assets/pixiv/` 和 `assets/baozhen/` 仅作参考，不加入首版 Asset Catalog、Target Membership 或 Copy Bundle Resources；逐项来源状态见 [素材记录](../assets/SOURCES.md)。

### 初始状态与控制

- 默认冬服，原图按比例显示，高度 256 点；缩放范围 240–480 点，不改变宽高比。高度仅指完整图片显示区域，不包含动画留白。
- 原图高度 516 像素，在 2× Retina 下默认 256 点约对应 512 像素；较大尺寸会放大原图，480 点约对应 960 像素，允许出现放大柔化，不作为原生清晰度验收基准。
- 图片显示区域四周各留 8 点透明空间，窗口尺寸为图片宽高各加 16 点；留白仅属于布局，不修改原始图片。窗口位置与屏幕边界夹紧均使用含留白的窗口外框。
- 第一次启动位于主屏幕可用区域右下角，窗口外框距右边缘 16 点，窗口底边贴合 `visibleFrame` 底边；静止图片底边因此距可用区域底边 8 点。该区域避开菜单栏和 Dock。
- 允许自由拖动；拖动超过 4 点判为拖拽，结束后不再触发点击。释放时将窗口限制在当前显示器可用区域内。
- 保存服装、尺寸、位置、显示器标识、置顶和动效偏好。目标显示器不可用或恢复位置越界时，移到主屏幕可见区域并夹紧边界。
- 默认置顶，只在普通桌面显示；跟随普通桌面切换，不覆盖其他应用的全屏空间。桌宠本体平时不主动激活应用或占用键盘焦点。
- 左键点击人物展示区域打开聊天；输入面板打开后才激活输入焦点。Escape 收起面板并恢复原先操作焦点。
- 鼠标穿透是整个桌宠窗口的显式开关，不承诺首版逐像素穿透。穿透开启时关闭交互面板，从菜单栏可重新打开聊天或关闭穿透。穿透状态每次启动默认关闭，避免失去交互入口。
- 菜单栏包含打开聊天、夏服／冬服、缩放、置顶、鼠标穿透、启用动效、隐藏／显示、设置和退出。打开聊天或显示命令会恢复可见状态；隐藏时关闭面板但保留内存会话。

### 动效

仅使用整体轻微位移和点击缩放，不暗示已有眨眼或口型素材。浮动幅度不超过 2 点、周期约 4 秒，点击缩放幅度不超过 2%、约 0.15 秒后恢复。以图片中心为缩放锚点，不裁剪到未变换的图片显示区域。在最大 480 点高度下，单侧缩放扩展最多 4.8 点，加 2 点位移仍小于 8 点留白，图片及版权文字须始终位于窗口内。动效围绕固定的窗口位置执行，不导致位置记忆漂移；隐藏、休眠或用户关闭动效时停止，释放展示器时撤销动画任务。

## 4. 聊天交互与角色表达

### 界面与触发

- 人物点击打开附近的聊天面板，包含本次会话、输入框、发送、取消、清空和关闭入口。面板约 360×420 点，贴近角色并保持在屏幕可用区域。
- 面板优先放在角色左侧，空间不足时改放右侧或限制在屏幕内。最新有效回复显示在角色旁可关闭的气泡里；长文本可滚动，面板在界面历史保留范围内展示完整回复。
- Enter 发送，Shift+Enter 换行；中文输入法候选确认期间不发送。空白消息不发送，单次输入上限 2,000 个 Swift Character。
- 发送后显示“正在回复”。聊天与测试连接共享一个在途请求名额，等待期间可取消；发送、重试、测试连接等其他请求触发入口均禁用，输入编辑、窗口交互仍可用。非流式返回有效完整回复后一次更新界面。
- 首次启动显示本地问候“你好，我是千早。今天过得怎么样？”，标明这是应用编写的问候，不计入模型会话。
- 不设置后台定时模型调用。只有发送消息和点击测试连接触发云端请求；测试连接结果不进入会话。

### 默认角色提示词

主动闲话补充（2026-09-09）：使用独立本地原创台词库与非激活气泡，不进入成功会话或待重试状态；不调用云端、不读取屏幕。默认开启，空闲间隔随机 3–7 分钟，可切换 1–3 或 10–15 分钟，偏好写入 UserDefaults。避让聊天、设置、请求、输入草稿、回复气泡及穿透状态；隐藏、睡眠清理闲话并重置计时。恢复后完整等待新间隔，不补发。最近 8 句去重，时段问好按本地小时选择，气泡约 12 秒自动关闭。菜单支持立即说一句和开关。原创闲话遵循默认人设，独立于用户编辑的云端提示词。

以下是可编辑的同人演绎设定，不是从游戏提取的官方对白，也不保证模型准确复现全部原作设定：

> 你正在扮演《少女爱上姐姐2》中的妃宫千早，作为用户桌面上的文字聊天伙伴。默认使用简体中文，以礼貌、克制、细腻而自然的方式交谈，避免每句话都使用夸张的语气或动作描写。日常回复通常为一至三句，用户需要详细解释时可以展开。不要主动透露原作关键剧情；不确定的原作细节不要编造。不要声称能看到用户屏幕、读取文件、执行操作，或记得本次提供的会话以外的经历。不要把生成的台词称作原作对白。用户询问应用或模型身份时如实说明这是千早的同人桌宠演绎。以“你”称呼用户，用户在本次聊天指定称呼后再调整。

设置中提供编辑及恢复默认入口。保存修改或恢复默认后，取消正在进行的请求、清空会话和旧气泡，避免新旧设定混用。提示词可跨启动保存，但不会从聊天中自动生成长期记忆。

### 内存会话与上下文

- 界面历史与请求上下文分别管理；一轮指一次有效的 user 输入及对应 assistant 回复。所有字符限制均按 Swift Character 计数，不是字节或 token 上限。
- 界面历史只存于内存，最多保留最近 50 轮、100,000 个 Swift Character（user 与 assistant 正文合计）。加入一轮后任一上限超出，即按完整轮次移除最早内容直至同时满足两项限制；显示固定本地提示“较早消息已从本次内存记录中移除”，不逐次累积提示，也不发送给模型。关闭面板或隐藏桌宠不清空保留范围内的历史。
- 每次请求从保留的成功历史构造近期上下文，最多 10 轮、12,000 个 Swift Character；超限时从请求副本中移除最早完整轮次，直至同时满足限制，不因此删除界面历史。若最新一轮单独就超过 12,000 字符，该轮也不发送，允许历史上下文为空。
- 请求始终另加当前 system 提示词与当前输入；它们不计入 12,000 字符历史限制。界面可以显示比模型实际收到的更多历史，不承诺模型记得所有可见内容。
- 单条 assistant 回复最多接纳 20,000 个 Swift Character；超过时整条作为响应过大错误，不显示部分正文、不计入成功历史，保留输入供重试。配合单次输入 2,000 字符上限，一轮最多 22,000 字符，不会单独突破界面历史容量。
- 请求失败或取消可在界面保留一个待重试输入及当前错误状态，但不能把失败或未完成的一轮加入成功历史或上下文；新请求替换旧待处理状态，重试不重复添加相同的用户消息。测试连接没有会话输入，不改变聊天待重试内容。
- 清空时取消请求并增加会话代次标识；返回结果必须匹配当前代次，防止已取消的迟到回复重新出现。退出时丢弃所有会话。
- 不保存聊天数据库、聊天文件、摘要或恢复快照；网络使用临时会话并关闭磁盘缓存，日志不写入请求正文、回复正文或密钥。
- 应用的本地不保存承诺不代表云端服务不保存；设置页用一句话说明请求将发送给用户配置的服务。

## 5. 模型接口与设置

### 配置和凭据

- 配置项：HTTPS API 基础地址、模型名、API Key、测试连接、角色提示词。首次启动基础地址和模型名为空，以说明性占位提示引导填写；不内置可用账户或密钥。
- 基础地址必须是有效 HTTPS URL，不含用户信息、query 或 fragment，允许包含服务要求的版本路径，例如 `https://example.com/v1`。去除末尾斜杠后追加 `/chat/completions`，不自动添加 `/v1`。占位地址不可作为有效默认配置。
- 模型名由用户填写，去除首尾空白，不能为空；首版不调用模型列表接口或自动选择模型。
- API Key 按用户于 2026-09-13 的明确选择，以明文与服务地址、模型名共同保存在项目根目录 `config.json`，字段为 `baseURL`、`model`、`apiKeys`，密钥表按规范化服务基础地址区分，文件权限 0600；保存连接时三者作为一个文档原子替换。角色提示词与其他偏好保存在 UserDefaults。切换服务不向新服务沿用旧密钥，也不自动迁移聊天上下文；保存地址、模型或密钥变更后取消请求并清空会话。应用和测试均移除钥匙串调用。升级脚本校验并迁移旧本地配置／音乐后删除原目录，应用不再读写 Application Support 下的这两类数据。
- 提供清除当前服务密钥入口。读写失败时显示错误；文件损坏时不覆盖原数据，保存使用同目录临时文件原子替换。
- 配置不完整时允许桌宠正常显示、拖动和换装；聊天发送入口引导配置，不发出无效请求。

### 兼容接口子集

使用 URLSession 发出 HTTPS POST，请求头为 `Content-Type: application/json` 和 `Authorization: Bearer <API Key>`。请求正文仅包含以下能力：

```json
{
  "model": "用户配置的模型名称",
  "messages": [
    { "role": "system", "content": "当前角色提示词" },
    { "role": "user", "content": "用户输入" }
  ],
  "stream": false
}
```

历史存在时，将成功的 user/assistant 轮次插入 system 与当前输入之间。读取 `choices[0].message.content` 的文本回复；不请求图片、音频、工具或供应商专属参数，不强行发送可能不兼容的温度和 token 参数。

只承诺支持上述文本 Chat Completions 子集，不宣称兼容所有供应商或模型。不兼容 system 消息、鉴权方式或返回结构的服务应明确报错，不静默改用其他端点。接口约定依据 [OpenAI Chat Completions 文档](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)。

测试连接使用同一请求路径和设置页当前草稿中的地址、模型及密钥，发送简短的“请回复：连接成功”，不附加角色提示词或会话；提示测试可能产生一次请求费用。成功标准是收到符合回复长度限制的有效文本，而不是逐字匹配模型回复。测试本身不保存配置或密钥，不进入聊天记录、气泡或角色上下文。网络请求不允许跨主机重定向携带鉴权信息，端点重定向时提示用户填写最终地址。

### 请求生命周期

- 聊天使用已保存配置，测试使用当前设置草稿；发起时捕获地址、模型和密钥的内存快照、唯一请求标识、配置代次。聊天另外捕获会话代次；测试另外捕获设置草稿代次。进行中的请求不重新读取可变设置。
- 任意时刻只允许一个有效在途请求；重复点击测试、发送或重试不创建第二个请求。取消时先使请求标识失效，再取消底层任务并释放名额；旧任务的完成或清理回调不得覆盖新请求状态。
- 修改测试所用地址、模型或密钥立即增加草稿代次、取消在途测试并清除旧测试结果；即使改回原值，旧结果也不得恢复。草稿编辑尚未保存时不改变聊天使用的已保存配置。
- 保存服务配置、角色提示词或恢复默认提示词时，先使当前请求失效并取消，增加配置及会话代次，清空聊天、旧气泡及测试状态；随后持久化设置。密钥文件操作失败时提示失败，不启用未成功保存的新配置。删除当前服务密钥也执行同样的失效处理，清除草稿中的该密钥。
- 回复、测试结果和错误均须匹配当前请求标识、配置代次及所属的会话／草稿代次，才允许更新 UI。测试状态明确表示“当前填写配置测试成功／失败”，不把服务 A 的结果显示为服务 B 的验证结论。
- 清空会话、主动取消或退出时先使相应状态失效，再停止请求；清空会话同时取消在途测试并清除测试状态。隐藏桌宠不自动取消已由用户发起的请求，也不新增请求。

### 错误和取消

聊天和测试连接每次请求的总等待上限均为 60 秒，超时取消。不得自动重试；聊天保留用户输入并提供手动重试，测试仅更新设置页状态。模型因长度限制截断时，若返回文本有效且不超过 20,000 字符，显示已有文本及截断提示并作为一轮接纳，不自动续写；超过本地回复上限则优先按响应过大处理。

| 情况 | 用户可见行为 |
| --- | --- |
| 配置缺失或 URL 无效 | 定位到设置字段并说明如何填写 |
| 401／403 | 提示检查密钥、权限或账户，不显示密钥 |
| 404 或供应商明确报告模型不存在 | 提示检查基础地址和模型名称；404 不一律认定为模型错误 |
| 429 | 提示额度或请求频率受限，允许稍后手动重试 |
| 5xx | 提示服务暂不可用 |
| 离线、TLS 错误或超时 | 提示连接失败或超时，不禁用 TLS 校验 |
| 空 choices、空文本、非 JSON 或不兼容结构 | 提示未收到可用文本回复，保留输入 |
| 回复超过 20,000 个 Swift Character | 提示响应过大，不显示部分正文或加入历史；聊天保留输入，测试显示失败 |
| 主动取消、清空、切换配置或退出 | 停止请求，忽略迟到结果，不显示为成功回复 |
