## 现状与故障边界

游戏身体和原脸是独立 PNG；身体内的银发、衣服、旧手已经合并。项目未提供独立前／后发、手臂或 PSD/KRA/ORA/CLIP 源工程，这不证明游戏封包内没有；项目设计以已提供 PNG 为输入，不把游戏资源解包列入本轮动作。[设计边界](../DESIGN.md) 身体 alpha 描述人物对外部背景的覆盖，不能直接当成每束头发对衣服的 alpha。内部交界若已混色，仅凭一个 RGBA 像素也不能唯一反推出两层颜色与透明度；这是合成公式的直接推论。[W3C 合成公式](https://www.w3.org/TR/compositing-1/#simplealphacompositing)

必须区分三类“缺发”：原图画布裁掉的头顶；原手／袖遮挡后未知的发束；编辑蒙版漏保或破坏的已有发束。`chi_d@.png` 的头顶已在 y=0 裁切，606 高母图继承这一状态；运行近景另补到 670 并下移 64 行，两个坐标系不能混用。[运行资源说明](../development/IMPLEMENTATION.md)

现有[粉裙近景组装脚本](/Users/red/Project/ChihayaPet/ArtSources/CharacterExpansion/native-tea/d/close/v1/assemble.cjs:60)先缩放生成躯干，再分段调整纵坐标；在行范围内用“中性银色”阈值选发，按前景多边形取消保护，最后羽化回填。颜色接近的白袖可能混入，暖色受光或深阴影的银发可能漏出；自选 hair mask 内差异为零只证明选中的像素未变，不能证明发束完整。脚本对 RGBA 四通道直接插值；它意在替换局部，和 source-over 意图不同。半透明边缘的 RGB 未按 alpha 加权、羽化带混入旧袖边，是待验证风险，不能据此认定所有涂层异常的根因。原脸整数坐标叠加也不能修复母图自身的接缝。[W3C alpha 加权规则](https://www.w3.org/TR/compositing-1/#simplealphacompositing)

## 抠图、分层和补绘各做什么

整人去背景只得到人物轮廓；本项目已有透明底，关键是语义分层，即给前发、后发、身体、袖臂、手、杯、碟各自可编辑的可见区域。SAM 2 可由点／框等提示取得候选分割；其默认输出经阈值转为二值 mask，模型 logit 也不是物理 alpha。因此它可辅助选区，不能直接承担发丝边缘或完整隐蔽部件恢复。[SAM 2 官方源码](https://github.com/facebookresearch/sam2/blob/main/sam2/sam2_image_predictor.py)

matting 专门估计渐变 alpha。ViTMatte 需要图像和 trimap，区分确定前景、确定背景、边缘未知区；可作为困难边界的候选，未验证其在这套银发线稿上的质量。已有外轮廓 alpha 优先直接保留；内部发／衣交界才考虑小范围 matting。alpha 估计不能单独消除 RGB 中已混入的衣色，仍须边缘颜色估计或小块补绘。不要为所有发束统一模糊羽化，否则细线会变薄。[ViTMatte 官方用法](https://github.com/hustvl/ViTMatte)、[模型接口](https://huggingface.co/docs/transformers/model_doc/vitmatte)

被旧手遮住的发束／布料没有可提取的真实像素。先找同服装、同视角其它原件；找不到时只能重建。邻近纹理复制适合小块连续布料，跨发束线条、卷发或褶皱则需局部补绘／生成；复制、镜像、生成均标为新绘，不能登记为原像素恢复。Live2D 官方分层教程同样要求拆前／侧／后发，并补画源图被挡住的部分；这里仅借鉴素材整理方法，不要求采用其动画系统。[官方分层教程](https://docs.live2d.com/en/cubism-editor-tutorials/psd/)

## 推荐的 agent 流程

1. 冻结本服装／视角／取景的身体、原脸和画布坐标，记录文件 SHA-256、裁剪框、整数 offset、参考锚点。原脸可能带刘海或领口，保持原 PNG 为完整单位；新衣和转向须重新验证配对，不能因尺寸相同而套用。[项目美术标准](../art-direction/chihaya-game-original-authority.md)、[原脸配对计划](../plans/2026-09-30-native-tea-and-original-faces.md)
2. agent 先建立少量命名图层与可编辑蒙版，保存发束／袖口的 SVG 路径；SAM 只提候选，路径以轮廓、线条及遮挡关系校正，颜色阈值不当真值。优先用专业软件的层／蒙版操作和确定性脚本组织材料，用户只需指出可见瑕疵，无需先学绘画。GIMP 的灰度层蒙版可编辑、路径可导入／导出 SVG。[层蒙版](https://docs.gimp.org/3.0/en/gimp-dialogs-structure.html)、[路径](https://docs.gimp.org/3.0/en/gimp-path-dialog.html)
3. 为每束发标注“保留原像素／被新动作遮住／原图未知须新绘”。移除旧袖臂后，先填补将露出的布料／发束，再制作新手臂和茶具。当前会话内置 imagegen 接口提供 prompt 和参考图，没有可传入的逐像素 mask 参数；生成结果须再次由保存的蒙版限制写入，不能靠提示词锁住区域外像素。
4. 保存“谁在谁前面”的遮挡有向无环图，而非固定整层顺序。例如同一发束可在袖后、杯前，应拆成前后片并共用来源／变换；握杯手指与杯柄也可拆片。拆出的像素从原底层移除，防止重复边缘；保留核心、边缘处理和新绘补片分别记所有权。每条遮挡和每块未知区都能在审核图定位。
5. 新部件先按领口、肩、腕等对应锚点平移／仿射配准；原头、原脸和受保护发束不重采样。小范围非刚性变形只用于新部件、记录控制点；改变角度、强弯曲或露出背面时转为新绘，不强拉旧片。OpenCV 的 ECC 依赖强度相似且需合理初始对齐，不宜在已换动作的整幅躯干上盲用。[仿射变换](https://docs.opencv.org/4.x/d4/d61/tutorial_warp_affine.html)、[ECC 说明](https://docs.opencv.org/4.x/dc/d6b/group__video__track.html)
6. 新层按明确遮挡顺序做 alpha 合成；若局部确需 crossfade，在预乘 alpha 表示下处理，保留原始 RGBA 作为可回退来源。专业编辑工程、分层 PNG、路径、蒙版、遮挡图、变换与生成来源一起保存，最终扁平 PNG 仅作交付结果。

## 样片与失败回退

建议先用粉裙近景作高风险样片：它同时涉及抬手遮发、浅袖与银发混淆、领口配准；再用夏服侧身检验视角／原脸绑定。先做“拆层后还原原站姿”，未改像素须重合成一致，查出重复边缘与遗漏；需要重新估计的内部混色边缘单列，不伪称原像素保留。

再验证喝茶：受保护像素完整性、旧袖／手残留、未知区是否补齐、发束连续、杯柄穿指、浅深底色边、原脸切换及 240／256／480 点显示。区域外像素不变只是一个 gate，不能证明艺术质量。路径失败先调整可见小区；matting 失败回到已知 alpha／路径；补片或新姿态失败则回退该层、缩小生成范围。只有反复失败的具体发束／褶皱才升级为人工画师修补，优先让 agent 完成可复现步骤。
